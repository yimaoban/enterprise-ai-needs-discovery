# 报告指引

报告应写本企业的具体内容，不堆通用 AI 宣传语。对关键判断标注“回答人陈述／材料已核实／他人意见／AI 推断或建议／待确认”。没有资料或样例验证时，不承诺可行性和成效。若提前结束，在标题或摘要中标明“阶段性需求挖掘报告”。

生成前先用不超过五条简短内容归纳：发现的机会、建议优先场景、AI 的具体贡献、关键条件与边界、验证办法。仅当用户尚未明确要求出报告时，再问一道选择题确认：基本准确并生成／需要调整／还有遗漏／先生成阶段性报告。用户选择调整或遗漏后，下一轮只问一道定位问题。

建议正文包括：

1. **企业与访谈范围：** 业务背景、当前目标、回答人的职责和知情范围、参与者与材料来源。
2. **机会清单与比较：** 各候选场景的实际工作、可能的 AI 贡献、价值依据、资料条件、主要风险、初步优先级和理由。明确普通软件、流程整理、人工判断或暂不实施更合适的情况。
3. **优先需求：** 最近真实事例及证据状态、当前流程、输入和期望输出、AI 与人工分工、最小试做范围。
4. **落地条件：** 数据和业务知识准备、授权与安全边界、使用环境、必要系统衔接、推动与维护人员、资源限制。
5. **验收与下一步：** 现状基线或待测项、检查任务与方法、最关键的错误、人工复核或停止条件、验收人、下一步行动、负责人和期望时间。
6. **待确认事项：** 未知事实、未验证推断、缺少材料、需要谁核实、八个方向中尚未覆盖的部分。关键未知会如何影响结论也应写明。

不设固定页数；不为填满模板而编造内容。区间数据保持原区间及来源，不推算精确收益。报告更新时保留已核实内容与修改来源；不同企业的报告分开存放。
